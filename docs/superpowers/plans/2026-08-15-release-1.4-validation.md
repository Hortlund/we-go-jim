# WGJ 1.4 Release Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove WGJ 1.4.0 can migrate real 1.3 data, survives critical user journeys, and ships with correct versioning, signing, entitlements, and Development/Production isolation.

**Architecture:** A fixture manifest and four file-backed v1.3 stores exercise the same container topology used by the app. Deterministic Development launch arguments drive UI smoke failures without Production services. Final gates inspect built products, signed device entitlements, archive contents, and runtime isolation.

**Tech Stack:** Swift 6, SwiftData SQLite stores, XCTest/XCUITest, xcodebuild, simctl, codesign, Xcode 26, iOS device signing.

## Global Constraints

- All destructive, migration, CloudKit, and profiling validation runs through `WGJ Dev`.
- Never install an Xcode Production build over the user's App Store/TestFlight Production app.
- The signed Development app and widget must contain only `.dev` identifiers.
- App and embedded widget must both report marketing version `1.4.0`, build `1`.
- A release gate is not passed unless its command output or device evidence is recorded.
- Preserve the user's unrelated `WGJ/WidgetShared/Localizable.xcstrings` change.
