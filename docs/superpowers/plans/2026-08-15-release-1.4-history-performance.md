# WGJ 1.4 History and Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix deterministic history paging, bounded analytics retry, Progress freshness/loading, and exercise-chart recomputation without speculative UI rewrites.

**Architecture:** Persistence queries return immutable Sendable page inputs through total-order cursors and bounded child batches. Retry and refresh policies are pure testable state machines. Progress and exercise charts move expensive hydration/projection behind generation-aware controllers while SwiftUI stays presentation-only.

**Tech Stack:** Swift 6, SwiftUI Observation, SwiftData, Swift Concurrency, XCTest, Xcode 26.

## Global Constraints

- Completion order is date descending then workout UUID descending.
- No full completed-workout fetch is allowed on History or Progress interaction paths.
- SwiftData models never cross actor boundaries.
- CloudKit work is forbidden on projection, pagination, selection, and refresh paths.
- Optimize only the confirmed P1/P2 findings; profile the remaining hypotheses before changing them.
- Preserve the user's unrelated `WGJ/WidgetShared/Localizable.xcstrings` change.
